# LCD and OLED display modes

The user's purchase screenshot identifies **1602 16×2 Character LCD Module
Display HD44780 with I2C**, blue variant. This is the first screen to integrate;
A provisional SSD1306 service is also prepared for the 0.96-inch 128×64 OLED;
its controller and supply voltage still need physical confirmation.

## Main sketch

Open `Eggcelerate/Eggcelerate.ino`. Keep `EggcelerateFirmware.h`, `LcdDisplay.h`,
`OledDisplay.h`, and the existing private `CloudConfig.h` in that folder. The LCD service uses
**hd44780 by Bill Perry, version 1.3.2**, installed in the local Arduino library
folder. The firmware probes common LCD addresses 0x27 and 0x3F and lets the
library configure that backpack’s pin mapping. It excludes 0x3C/0x3D from LCD
detection to avoid sending LCD commands to the OLED. A different LCD address
requires updating the candidate addresses after identifying the module.

OLED dependencies already installed locally: Adafruit SSD1306 2.5.17, Adafruit
GFX and Adafruit BusIO. OLED address detection probes 0x3C/0x3D; if both respond,
it disables the OLED service rather than selecting an ambiguous device. Address
acknowledgement does not identify the controller or prove visible output.

I²C pins follow the schematic: **SDA GPIO21, SCL GPIO23** at 100 kHz.
The firmware explicitly sets them before the LCD library initializes Wire.

## Display switching

| Mode | LCD | OLED |
| --- | --- | --- |
| Protected setup AP open | Temperature/humidity | Pairing code and Online/Offline, with SETUP header |
| Normal operation | Temperature/humidity | Pairing code and Online/Offline |

The LCD always keeps the larger temperature and humidity readout visible. The
OLED shows the pilot’s fixed code **EGG01**, including outside setup mode.
A commissioned identity is required; otherwise it shows Not commissioned.
No Wi-Fi, AP, or MQTT passwords are displayed. The OLED status uses size-2 text;
the short code uses size-3 text, occupying 90×24 pixels. Legacy ten-character
codes remain supported and use size-1 text to fit without clipping.
OLED headings SETUP/EGGCELERATE and PAIRING CODE are uppercase and both use
size-1 text; ONLINE/OFFLINE remains size 2, and EGG01 remains size 3.
All four OLED lines are left-aligned at x=0: EGGCELERATE (or SETUP),
ONLINE/OFFLINE, PAIRING CODE, and EGG01. Font sizes remain 1, 2, 1 and 3.

Online means Wi-Fi and MQTT are connected and a matching database receipt was
received less than 45 seconds ago. Wi-Fi alone is not Online. Opening setup does
not force Offline while the server connection still works. The status reflects
sensor delivery, not actuator capability.

Normal LCD output (Celsius):

```text
Temp: 29.1 C
Hum:  87.6 %RH
```

The service reuses the existing DHT22 sample, refreshes at most once per second,
and only writes changed rows. It pads each row to erase leftover characters
without repeatedly clearing the display. Sensor failure or readings older than
five seconds show an explicit unavailable/stale message. Wi-Fi is not needed
to display local measurements. Dashboard unit settings are not synchronized yet.

Initialization/write failure disables the LCD service and prints a diagnostic;
it does not halt the sensor/cloud loop. After correcting a missing/disconnected
display, restart the ESP32 to initialize it again. I²C transactions use a bounded
25 ms timeout; the LCD initialization is a one-time operation during startup.

## Electrical connection before upload

The exact backpack power rating and current wiring still need confirmation.
Standard 5 V LCD backpacks may have SDA/SCL pull-ups to 5 V. Do not connect those
signals directly to the ESP32. For a 5 V backpack, use a suitable bidirectional
I²C level converter:

| ESP32 / low side | Converter | LCD / high side |
| --- | --- | --- |
| 3V3 | LV supply | — |
| — | HV supply | 5 V supply, if confirmed for this LCD |
| GPIO21 | LV data channel ↔ HV data channel | SDA |
| GPIO23 | LV clock channel ↔ HV clock channel | SCL |
| GND | Common GND | GND |
| — | — | VCC from the confirmed LCD supply |

Any other 5 V I²C module with pull-ups must also stay on the appropriate high
side; do not leave a direct 5 V time-module pull-up on the ESP32 side. The OLED
voltage remains unconfirmed, so do not connect it based on this LCD guide.

Once wiring is confirmed, upload the main sketch with NodeMCU-32S selected and
**Erase All Flash disabled**. This pilot revision migrates the old saved
ten-character code to EGG01 while retaining Wi-Fi and the AP password; do not
commission again. Serial Monitor is 115200 baud. Look for `LCD ready` or the
reported initialization status. If backlight is on but characters are absent,
adjust the backpack contrast trimmer gently.

Current state: both display services prepared; physical wiring, upload, controller identification, and display acceptance
pending. No firmware has been uploaded by this documentation step.
