## Baseline failure and disposition

The previous full suite had 114 passes and one failure in concurrent turn replay.
The failure occurred during concurrent `create_app()`/OpenAPI schema construction,
before the turn request or storage assertion. Shared route metadata produced a
Pydantic `UnsupportedFieldAttributeWarning`, which remains an error in pytest.

An initial full M0 rerun exposed the same setup problem in both parameterizations
of the device-assignment test. The alert-dismissal test also used that pattern.

Changed those three test setups to construct separate apps serially before racing
their requests, matching the existing mode/cycle/candling concurrency tests.
The turn test now uses a barrier and additionally asserts exactly one persisted
retry receipt. Device assignment still checks 201/409 for competing actions and
identical replay for the same key. Alert dismissal still checks exact replay and
farm isolation. No warning filter was weakened and no production code changed.

This verifies concurrent requests across initialized API instances. Concurrent
application-factory calls inside one process are outside these storage contracts
and remain unsupported by this test setup. This is not evidence of physical turn
execution or a change to device command semantics.

## Readings payload baseline

Measured one chamber in a unique disposable farm with synthetic samples every
30 seconds. Its active cycle started at `2026-09-12T00:00:00Z`; the sample range
ended at `2026-10-03T03:40:26Z`. Used the actual PostgreSQL readings HTTP endpoint
through TestClient. Each window was measured once, in the order below.

| Window | Points returned | Raw response bytes | Computed gzip bytes | Local request ms |
| --- | --- | --- | --- | --- |
| 24 hours | 2,879 | 382,927 | 16,424 | 67.93 |
| 7 days | 20,159 | 2,681,167 | 114,162 | 278.94 |
| Full cycle | 60,920 | 8,102,380 | 344,670 | 800.33 |

The request's moving end time explains the short-window point counts. Timing
includes local DB access and response serialization, not network transfer or
browser rendering. Gzip sizes were calculated afterward; they do not prove that
the deployment compresses API responses. Constant synthetic values may compress
better than real telemetry. This is a baseline, not a load/capacity qualification.
M4 still requires 1/12/100-chamber measurements, realistic varied signals, browser
work, chart bounds, and export completeness.

Reproduction script: [m0_readings_baseline.py](repro/m0_readings_baseline.py).
It rejects non-disposable database URLs and seeds only a newly generated farm;
the farm remains in the disposable test database until that service is recreated.
